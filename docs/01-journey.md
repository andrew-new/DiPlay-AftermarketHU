## 三个决定性转折

### 1. 连接：热点 > Wi-Fi Direct

三轮自编译全卡死在连接。根因：官方 Wi-Fi Direct 路径依赖 AOSP 灰名单 API
（`setWifiP2pChannels` 等），改装车机固件普遍不提供。**热点自动恢复**（AP 接口消失 5 秒自动重启）
才是解开连接的钥匙——这不是我们写的，是 H3 社区作者写好的。

附带发现：**iPhone 自己的个人热点开着会阻止连接**（吉利车实测同样现象）。

### 2. 音频：协商层，不是播放层

详见 [02-audio-fix](02-audio-fix.md)。诊断报告显示 iPhone 从不发起 `type=100` 音频流；
根因在 `/info` 的 audioFormats 协商声明（Opus 被清零），不在 AudioTrack。
7 号包的教训：改播放端 = 对着没有水的河修桥。

### 3. 卡顿：积压策略，不是解码速度

详见 [03-lag-analysis](03-lag-analysis.md)。60% 画质档（解码量 -64%）依然卡 → 排除解码吞吐；
catch-up 生效后仍卡 → 排除反复 flush 循环为主因 → 主嫌疑转为**端到端延迟**
（`touch2frame` 实测指标，待实车数据）。

## 一句话复盘

**赢在「找对层」：连接靠热点路径、音频靠协商声明、卡顿靠积压策略——每一层都有社区作者
用实车验证过同款方案，我们的工作是把它们拼到同一台车机上，并守住「不影响已验证功能」的边界。**
